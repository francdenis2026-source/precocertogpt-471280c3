# Auditoria SEO completa — PreçoCerto

Data: 2026-08-17
Alvo: https://www.precocerto.live
Ferramenta: SEOmator 3.0.1
Execução: GitHub Actions — SEO Audit run 3

## Cobertura

Foram auditadas 27 URLs de forma individual para contornar a limitação de descoberta de rotas da SPA:

- 15 rotas públicas listadas no sitemap;
- 6 páginas representativas de produtos;
- 4 páginas de estabelecimentos reais;
- 2 páginas de estabelecimentos de demonstração.

Rotas privadas de administração não entram em SEO público e não devem ser indexadas.

## Resultado geral

A ferramenta atribuiu 96/100 a todas as URLs. Esse número precisa ser interpretado com cuidado: o HTML inicial entregue pelo React é praticamente o mesmo em todas as rotas, e grande parte do conteúdo, links e headings aparece somente depois da execução do JavaScript. Portanto, a pontuação alta do shell não significa que cada página dinâmica esteja otimizada para busca.

## Problemas críticos recorrentes

Os seguintes problemas apareceram nas 27 URLs auditadas:

1. HTML inicial sem H1 detectável.
2. Conteúdo inicial extremamente fino: o crawler encontrou 0 palavras relevantes antes da renderização JavaScript.
3. Ausência de hierarquia de headings no HTML inicial.
4. Canonical global apontando para https://precocerto.live/ inclusive em páginas internas; em 25 páginas internas a ferramenta classificou isso como canonicalização indevida para a homepage.
5. A versão www e a canonical sem www estão inconsistentes.
6. URLs inexistentes retornam 200, caracterizando soft 404.
7. O redirecionamento HTTP foi detectado apontando primeiro para uma URL HTTP em vez de HTTPS.
8. Ausência de Content-Security-Policy e de proteção X-Frame-Options/frame-ancestors.
9. Permissions-Policy ausente.
10. Nenhum link interno é encontrado no HTML inicial; a navegação é predominantemente injetada por JavaScript.
11. As 15 URLs do sitemap aparecem como órfãs para o crawler porque não há links rastreáveis no HTML inicial.
12. Estrutura semântica insuficiente no HTML inicial para mecanismos de IA/GEO: ausência de main, headings hierárquicos, parágrafos e estruturas de conteúdo antes da hidratação.
13. llms.txt não foi encontrado.
14. Páginas internas não possuem BreadcrumbList consistente no HTML auditável.
15. Falta de sinais E-E-A-T rastreáveis no shell: links claros para Sobre, Contato e Política de Privacidade.

## Performance

- Mediana de resposta observada: ~580 ms.
- A maioria das rotas ficou acima da recomendação de 500 ms da ferramenta.
- `/padarias` apresentou uma ocorrência crítica de 12.762 ms e foi classificada como timeout para crawler.
- LCP observado variou aproximadamente de 0,49 s a 2,46 s nesta rodada.
- Fontes não possuem preload detectável.
- O servidor foi detectado usando gzip em vez de Brotli.

## Produtos e estabelecimentos

As URLs dinâmicas com UUID também receberam alerta por pouca qualidade semântica da URL. Produtos atualmente não possuem slugs descritivos no banco, então URLs como `/produto/<uuid>` perdem contexto de palavras-chave e legibilidade. Estabelecimentos reais testados também utilizam UUID quando não possuem slug.

Recomendação: gerar slugs estáveis e descritivos para produtos e estabelecimentos, mantendo redirecionamento 301 dos identificadores antigos quando necessário.

## Prioridade de correção

### P0 — indexação e canonicalização

- Gerar title, meta description e canonical específicos por rota.
- Garantir que cada rota pública possua HTML rastreável com H1, conteúdo textual e links internos, idealmente via prerender/SSR ou geração estática das rotas públicas.
- Corrigir soft 404 para retornar HTTP 404 real em URLs inexistentes.
- Definir domínio canônico único (www ou sem www) e redirecionar todas as variações diretamente para HTTPS.

### P1 — produtos e estabelecimentos

- Criar slugs descritivos para produtos e estabelecimentos.
- Adicionar Product/Offer e LocalBusiness/Store JSON-LD por página.
- Adicionar BreadcrumbList nas páginas internas.
- Inserir links HTML rastreáveis entre setores, estabelecimentos e produtos.

### P1 — segurança técnica

- Adicionar CSP com frame-ancestors.
- Adicionar Permissions-Policy.
- Revisar HSTS/preload e redirecionamento HTTP→HTTPS.

### P2 — confiança e IA/GEO

- Criar/fortalecer páginas Sobre, Contato e Política de Privacidade e conectá-las ao footer.
- Adicionar llms.txt.
- Garantir estrutura semântica main/article/section e headings coerentes no HTML pré-renderizado.

### P2 — performance

- Investigar o pico de `/padarias`.
- Implementar preload seletivo das fontes críticas.
- Avaliar Brotli/CDN/cache para assets e HTML.

## Conclusão

O PreçoCerto possui uma base visual e técnica funcional, mas a arquitetura atual de SPA client-side esconde grande parte do conteúdo dos crawlers que analisam o HTML inicial. O ganho de SEO mais importante não virá de pequenos ajustes de meta tags isolados, mas de tornar as páginas públicas de setores, produtos e estabelecimentos rastreáveis e semanticamente distintas antes/de forma independente da hidratação JavaScript.
